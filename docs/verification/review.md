# レビューによる検証の手順

要求の検証手段が `test` ではなく `review` の3件について、何をどう確かめるかを
書き留めたもの。手順が人の頭の中にしか無いと、確かめたつもりで確かめていない
状態が残るため。

対象は REQ-0050 / REQ-0053 / REQ-0055 の3件。要求そのものは
`docs/requirements/platform.yaml` にあり、こちらが正である。

実施時期はいずれもリリース用のタグを打つ前。REQ-0055 だけは実装の変更が
入るたびの PR レビューでも見る。

---

## REQ-0050 単一実行ファイルでの動作

> システムは外部のデータベースと追加の常駐プロセスを必要とせず、単一の実行
> ファイルで動作しなければならない

### 手順

```bash
cargo build --release --locked
file target/release/oci-cache
ldd target/release/oci-cache
```

1. `target/release/` に生成される配布対象が実行ファイル1つであること。
   設定ファイルと文書以外に、配備先へ配置しなければ動かないファイルが無いこと。
2. `ldd` の結果が、配備先の OS が備える共有ライブラリだけであること。
   データベースのクライアントライブラリが並んでいないこと。
3. `Cargo.toml` の依存に、別プロセスの起動または外部のデータベースへの接続を
   前提とする crate が無いこと。索引は redb（単一ファイル・同一プロセス）で
   あり、これは外部データベースに当たらない。
4. 何も無い作業ディレクトリで実行ファイルだけを起動し、事前の準備なしに
   待ち受けが始まること。

### 判定

上の4点すべてを満たすこと。1〜2 は `ci.yml` の「単一実行ファイルであることの
確認」ステップが毎回のビルドで出力しているので、その出力を読めばよい。
3〜4 は人が見る。

## REQ-0053 対応アーキテクチャ

> システムは linux/arm64 と linux/amd64 の双方で動作する実行ファイルを
> 提供しなければならない

### 手順

`release.yml` はタグを起点に、amd64 と arm64 のそれぞれのランナーで
ビルドする。手元で先に確かめたいときは workflow_dispatch から実行する。

1. release ワークフローの `build` ジョブが両アーキテクチャで成功していること。
   片方が落ちた状態で `publish` へ進んでいないこと。
2. リリースに `oci-cache-linux-amd64.tar.gz` と
   `oci-cache-linux-arm64.tar.gz` の両方が添付されていること。
   それぞれに `.sha256` が並んでいること。
3. 配備先の実機（amd64 の1台と arm64 の1台）で、展開した実行ファイルが
   起動して待ち受けに入ること。ここは実機でしか分からないので、
   ビルドが通っただけで済ませない。

```bash
sha256sum -c oci-cache-linux-arm64.tar.gz.sha256
tar xzf oci-cache-linux-arm64.tar.gz
./oci-cache-linux-arm64/oci-cache --config config.toml
```

### 判定

上の3点すべてを満たすこと。3 を省いた場合は、確認できていないものとして扱う。

## REQ-0055 常駐メモリ上限の実行環境への委譲

> システムは常駐メモリの使用量に自身で上限を設けず、実行環境が課す制限に
> 従って動作しなければならない

REQ-0052（自前で上限値を持つ方式）を置き換えた要求なので、実装の途中で
うっかり自前の上限が入り込んでいないかを見る。

### 手順

実装の変更が入る PR で、次の観点を見る。

1. 設定に常駐メモリの上限を指す項目が無いこと。`config.example.toml` に
   メモリ量を受け取るキーが増えていないこと。
2. 主記憶の使用量を測って動作を変える処理が無いこと。空きメモリを見て
   受け入れを絞る、確保量を数えて打ち切る、といった制御を持たないこと。
3. メモリ使用量を根拠にした上限を持つキャッシュ機構を使っていないこと。
   保存領域の上限（REQ-0026 / REQ-0027）はディスク容量に対するもので、
   これには当たらない。
4. blob の中継が全体を主記憶に載せない実装のままであること（REQ-0051）。
   ここが崩れると、上限を持たない方針が実行環境への負荷に直結する。

```bash
# 観点 1〜3 の当たりを付ける。該当があれば内容を読む
rg -n -i 'memory|mem_limit|rss|available_memory|sysinfo' src/ config.example.toml
```

### 判定

1〜4 のいずれにも該当が無いこと。該当した場合は、それが実行環境の制限に
従う実装（たとえば OS から渡された制限を読むだけで、自前の値を持たない）で
あることを確かめる。自前の上限値を持つならこの要求に反するので、実装を直すか、
要求の置換として扱う。
